# GitEdge Development Guidelines

## Overview

Full-stack monorepo that runs Git on the edge. Git objects live in blob storage,
refs in Redis, metadata in PostgreSQL.

- **Backend**: Python 3.14+ / FastAPI, Pydantic v2, SQLAlchemy 2, Alembic, dulwich
- **Frontend**: TypeScript / React 19, Vite, TanStack Router + Query
- **Tooling**: uv (`backend/`), Bun (`frontend/`), pre-commit for lint/format

## Commands

```shell
uv sync --locked                                  # Install Python deps (repo root)
bun install --frozen-lockfile                     # Install JS/TS deps (repo root)
cd backend && uv run python run_app_locally.py    # Backend (http://localhost:8000)
bun run dev                                       # Frontend (http://localhost:5173)
bun run --filter frontend build                   # Type-check + build frontend
pre-commit run -a                                 # Run all linters/formatters
```

## Backend Architecture

Keep layers focused; dependencies point inward:

- `app/api/routes/` — thin handlers; parse input and delegate to a service
- `app/services/` — business logic; orchestrate clients, no queries or storage access
- `app/clients/` — data access and external integrations; DB access goes through
  `*Store` classes built on `CrudStore` / `SQLStore`
- `app/schemas/` — Pydantic models; `app/entities/` — SQLAlchemy models
- `app/api/dependencies.py` — dependency wiring

## Python Standards

- PEP 8, type hints everywhere, specific types (`dict[str, str]`)
- `snake_case` functions/variables, `CamelCase` classes, `UPPER_CASE` constants
- Absolute imports only; line length 120; Google-style docstrings
- Pydantic v2 (`model_config`) and `pydantic-settings` `BaseSettings`
- Specify error types in `except` and log them
- Prefer returning "not found" over catching and ignoring exceptions
- Add an Alembic migration for every schema change

## Testing

- Backend: `cd backend && uv run pytest tests/unit` (coverage: `uv run coverage run -m pytest tests/unit`)
- Frontend: `bun run test`; watch `bun run --filter frontend test:watch`
- Unit tests must not touch a real DB, Redis, or blob storage — use the in-memory
  fakes in `tests/unit/utils/fakes.py` and inject them via FastAPI dependency
  overrides (see the `fake_stores` fixture)
- Integration tests use real dependencies (Docker/testcontainers)
- Use `pytest-mock`, not `unittest.mock`
- `asyncio_mode=auto`: write `async def test_...` directly, never `@pytest.mark.asyncio`
- Frontend tests: co-located `*.test.{ts,tsx}`, `describe`/`test` (never `it`), custom
  `render()` from `@/test/test-utils`, `vi.mock()` for modules

## Lint Commands

```shell
pre-commit run -a                        # Everything (preferred)
pre-commit run ruff-check --all-files    # Python lint
pre-commit run ty --all-files            # Python types
bun run lint                             # Frontend (Biome)
```

## Frontend Standards

- Biome: 2-space indent, double quotes, no semicolons, self-closing elements
- PascalCase components, `use`-prefixed hooks, kebab-case shadcn/ui primitives
- Import via the `@/*` alias; `import type` for types
- Arrow-function feature components; named exports for route components
- Keep route files thin; UI logic lives in `src/components/`
- React Hook Form + Zod for forms; TanStack Query for server state

## Never Edit Manually

- `frontend/src/routeTree.gen.ts` — generated by TanStack Router
- `frontend/src/client/` and `frontend/openapi.json` — regenerate with
  `bash ./scripts/generate-client.sh`
- `frontend/src/components/ui/` — shadcn/ui components
- `backend/resources/email-templates/build/` — generated by `bun run email:export`
- `bun.lock`, `uv.lock` — managed by the package managers
